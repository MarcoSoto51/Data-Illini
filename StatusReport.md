# Status Report


## Task Updates
#### Data Collection
For data collection, we have found three main FARS auxiliary datasets that we plan to use, and we reviewed the source information connected to them. This lets us understand what each dataset contains and how they will fit with one another. ACC_AUX provides accident-level information, PER_AUX provides information about people involved in crashes, and VEH_AUX provides vehicle-level details. The related artifacts for this task are ProjectPlan.md and the FARS 2023 auxiliary data folder in our repository.
#### Data Exploration
For data exploration, we looked over the structure of the datasets and started to think about which variables could be the most useful for analysis. This includes driver characteristics, vehicle information, crash conditions, and other factors that are related to fatal car crashes. We have also talked about possible problems that might show up later, like missing values, coded fields, and differences in how the three datasets are organized. Even though we have not done the full profiling in code, this step lets us understand the data more and plan for cleaning and integration.
#### Data Cleaning
For data cleaning, we have not fully started implementation yet, but we have a clear idea of what this step will involve. We will check for missing values, inconsistent formatting, and fields that need to be simplified before analysis. Since we are working with multiple related datasets, cleaning will also be crucial for making sure the variables line up correctly before trying to merge.
#### Data Integration
For data integration, we have clarified that ACC_AUX, PER_AUX, and VEH_AUX will all be connected using ST_CASE. This was the most important update in this milestone because earlier versions of our project plan did not clearly outline this process. We now have a direct and realistic plan for combining the datasets, and are actively working towards this. Our integration plan is described in ProjectPlan.md, and this status update in StatusReport.md reflects that revised direction.
#### Analysis and Visualization
For analysis and visualization, we have not produced any results yet, but we do have a clear plan for what comes next. After cleaning and integration, we will create summary statistics, charts, and possibly create a predictive model to explore patterns in fatal crashes. We will also look closely at how driver, vehicle, and environmental factors may be related to crash outcomes.

## Changes to Project Plan
Since Milestone 2, we have refined our project plan to improve clarity, feasibility, and alignment with our research objectives. In particular, we more clearly defined the datasets selected for analysis by specifying their scope, structure, and relevance. We also expanded our explanation of how these datasets will be integrated by outlining more concrete steps for merging, including the key variables used to link them and potential challenges related to compatibility and data quality. Additionally, we strengthened our discussion of potential data gaps and limitations by offering a more thorough assessment of missing or incomplete information and its possible impact on our analysis. These updates result in a more detailed and realistic project plan that better positions us for the next stages of data processing and analysis.

## Challenges Encountered
One challenge we faced was making sure the project scope was realistic. Early in our planning project, the planning process, the project direction was less focused, so it was not really clear how the datasets would actually connect or if the work we had to do would be manageable within the time we had. We covered this by revising the project plan so that it can clearly center on the FARS auxiliary datasets and explain how they relate to each other.

Another big challenge was clearly understanding the structure of the datasets well enough to fully explain the integration process. Because the project involves accident-level, person-level, and vehicle-level data, we were forced to think carefully about how those different levels of information would fit together. This was addressed by looking over the dataset descriptions more closely and identifying ST_CASE as the main variable that we will use to connect the dataset.

In addition, we know that missing values, coded fields, and inconsistent reporting could affect our analysis later. Because of this, we had to make sure that the updated project plan includes a clearer discussion of these issues and how they could affect the project. Even though we have not begun coding yet, identifying these problems now allows us to get a better starting point for the implementation phase.
